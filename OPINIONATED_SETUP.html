Opinionated Sablier Setup

A single-host Docker stack that runs a small fixed set of containers on demand, evicting them when memory pressure (typically VRAM) demands it — not when a timeout expires. Designed for AI inference workloads where cold starts are expensive and access patterns are uneven.

1. Why this exists

The upstream Sablier project is a generic scale-to-zero proxy. Its default eviction policy is purely time-based: a configurable session timeout fires and the container stops. That works fine for "internal admin tools accessed once a week," but it falls apart for AI inference workloads where:

  • Cold-start cost is large (30–90 s for a 7B LLM, several seconds for Whisper, etc.).
  • Memory (specifically VRAM) is a real, finite, shared budget across multiple model containers.
  • Some containers are hit every few minutes, others once a week, and you want both to behave well.

This fork adds a memory-pressure-aware eviction policy. Containers opt in by declaring sablier.peak_vram_mb on their Docker labels. Sablier keeps them loaded as long as the declared peaks fit within the configured budget. Only when a new request arrives that needs space does Sablier evict the lowest-priority loaded container (with oldest-last-used as the tie-break). Containers that opt in are also exempt from the time-based eviction — pressure becomes the only signal that ever stops them.

This document is the opinionated path through that fork: one Docker host, nginx in a container, a small fixed set of model containers, blocking-only API access. The setup has been verified end-to-end.

2. The shape of the deployment

                    ┌─────────────────────────────┐
   curl, SDKs ───▶  │ nginx  (port 8080)          │
                    │   /api/whisper/    ─┐       │
                    │   /api/embeddings/ ─┼─auth─┐│
                    │   /api/llm/         ─┘     ││
                    └────────────────────────────┘│
                              │ proxy_pass        │
                              ▼                   │
                    ┌────────────────────┐        │
                    │ model containers   │        │
                    │  whisper-test:80   │  ◀──── │
                    │  embed-test:80     │        │
                    │  llm-test:80       │        │
                    └────────────────────┘        │
                              ▲                   │
                              │ docker start/stop │
                    ┌─────────┴──────────┐        │
                    │ sablier (port 10000)│ ◀─────┘
                    │  /api/strategies/   │  auth_request
                    │   blocking          │
                    └────────────────────┘
                              │ /var/run/docker.sock
  • nginx handles all HTTP routing by path. Each route has an auth_request sub-call to Sablier that blocks until the matching container is ready, then nginx proxy_passes to the upstream.
  • Sablier manages the lifecycle of the model containers. It decides who is loaded, who gets evicted, and accounts for VRAM pessimistically against the budget you give it.
  • Model containers exist (docker create'd, present in docker ps -a) but stay Stopped until Sablier starts them. This is normal Docker behaviour: containers are persistent objects in the daemon's database, separate from being a running process.

3. Why these decisions

DecisionWhy
nginx runs in a container in the same compose file Single Docker network gives clean service-name DNS (nginx → sablier, nginx → whisper-test). Native nginx would force you to publish container ports and route by host IPs — workable but uglier and more brittle on a single host.
Stock nginx, no plugins or custom builds The Sablier–nginx integration listed in upstream docs is a proxy-wasm plugin requiring a special build. We don't need it: auth_request in stock nginx fires a sub-call to a URL before forwarding, which is exactly the integration we want for blocking-only flows.
Blocking strategy only (no dynamic / loading page) API clients (curl, OpenAI SDK, Whisper CLI) want a delayed real response, not an HTML interstitial. The dynamic strategy requires a plugin that can render templates; auth_request can't, so we don't try.
Path-based routing instead of host-based One hostname. No DNS / TLS cert plumbing per service. Easy to put behind a single TLS terminator later if you want.
Model containers not in the compose file The compose file is the stack. Model containers come and go on a different cadence. Keeping them out of compose means docker compose up never accidentally starts every model at boot. They live as docker create-only entries, only started by Sablier.
Lazy DNS via resolver in nginx Stock nginx resolves upstream blocks at config-load time. If your model container is Stopped at boot, that resolution would fail and nginx would refuse to start. Variables in proxy_pass + a resolver directive force per-request DNS, which only fires once a request actually arrives — by which time Sablier has started the upstream.
VRAM accounting is declarative, not measured Sablier doesn't shell out to nvidia-smi or query NVML. You declare peak_vram_mb per container as a worst-case budget. Sablier sums declared peaks against your --vram.total-mb. Pessimistic by design — concurrent decisions can't double-count, and you keep deterministic control over what Sablier thinks the GPU is doing.

4. Prerequisites

  • One Linux host with Docker Engine and the compose plugin (docker compose).
  • The Sablier image with this fork's VRAM patch. Either:
    • Build from the fork's source: docker build -t sablier:vram-dev -f build/Dockerfile.dev .
    • Or push your own tag to a registry and reference it.
  • Whatever tool you'll actually use the GPU through (vLLM, llama.cpp server, faster-whisper-server, etc.). For this guide, we use stock nginx images as harmless stand-ins so you can verify the wiring before plugging in real model servers.

6. The stack: docker-compose.yml

name: sablier-stack

services:
  sablier:
    image: sablier:vram-dev
    container_name: sablier
    restart: unless-stopped
    networks: [sablier-net]
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
    command:
      - start
      - --provider.name=docker
      - --provider.auto-stop-on-startup=true
      - --logging.level=info
      - --vram.enabled
      - --vram.total-mb=8000          # adjust to your GPU
      - --vram.headroom-mb=500
      - --sessions.expiration-interval=2s
      - --strategy.blocking.default-timeout=120s
      - --strategy.blocking.default-refresh-frequency=500ms

  nginx:
    image: nginx:1.27-alpine
    container_name: sablier-nginx
    restart: unless-stopped
    depends_on: [sablier]
    networks: [sablier-net]
    ports:
      - "8080:80"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./nginx/conf.d:/etc/nginx/conf.d:ro

networks:
  sablier-net:
    driver: bridge
    name: sablier-net
Why auto-stop-on-startup=true? When Sablier starts, it scans every container with sablier.enable=true. If any are running, it stops them so the system starts in a known clean state. If you have model containers you want to be running at boot regardless, set this to false and start them manually.

7. Sablier configuration knobs

FlagWhat it does
--vram.enabledTurns on the patched eviction policy. Without this flag the fork behaves identically to upstream Sablier (time-based eviction only).
--vram.total-mb=NThe VRAM budget Sablier will manage. Set it to what's available to Sablier-managed containers, not necessarily the GPU's installed memory. If another process always uses 4 GB, subtract it.
--vram.headroom-mb=NAlways-free buffer kept above the eviction threshold. Eviction triggers when free < new-peak + headroom. 5–10% of total is typical.
--sessions.expiration-interval=2sHow often Sablier scans for expired non-participants. For non-participants this is the resolution of TTL eviction. Keep it short.
--strategy.blocking.default-timeout=120sMaximum time a blocking call waits before returning 500. Set this longer than your slowest cold start. Per-request override available via ?timeout=.
--strategy.blocking.default-refresh-frequency=500msHow often Sablier polls the container's status during a blocking call. 500 ms is a good balance.

All flags can be set via SABLIER_* environment variables or in /etc/sablier/sablier.yaml. See sablier.sample.yaml.

8. nginx configuration

nginx/nginx.conf

user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log warn;
pid /var/run/nginx.pid;

events {
    worker_connections 1024;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    # Long timeouts because the auth_request subrequest blocks while
    # Sablier waits for the model to become healthy. Match this to your
    # slowest model's cold-start time (LLMs commonly take 30–90 s).
    proxy_connect_timeout 10s;
    proxy_send_timeout    180s;
    proxy_read_timeout    180s;

    log_format main '$remote_addr [$time_local] "$request" '
                    '$status $body_bytes_sent rt=$request_time '
                    'upstream=$upstream_addr ut=$upstream_response_time';
    access_log /var/log/nginx/access.log main;

    # Sablier API. Used only as the auth_request target.
    upstream sablier_api { server sablier:10000; }

    # Per-model upstreams are NOT defined as upstream {} blocks — see comment
    # in conf.d/server.conf. Lazy DNS via Docker's embedded resolver.
    resolver 127.0.0.11 valid=10s ipv6=off;

    include /etc/nginx/conf.d/*.conf;
}

nginx/conf.d/server.conf

server {
    listen 80;
    server_name _;

    # Health endpoint — verify nginx without waking anything.
    location = /healthz {
        return 200 "ok\n";
        add_header Content-Type text/plain;
    }

    # ─── /api/whisper/ → whisper-test ────────────────────────────────────
    location /api/whisper/ {
        auth_request /_sablier_whisper;
        # Variable in proxy_pass = lazy DNS via the `resolver` directive in
        # nginx.conf. Lets nginx start even when the upstream is Stopped.
        set $whisper_up "whisper-test:80";
        proxy_pass http://$whisper_up/;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
    location = /_sablier_whisper {
        internal;
        proxy_pass http://sablier_api/api/strategies/blocking?names=whisper-test&session_duration=2h&timeout=120s;
        proxy_pass_request_body off;
        proxy_set_header Content-Length "";
    }

    # ─── /api/embeddings/ → embed-test ───────────────────────────────────
    location /api/embeddings/ {
        auth_request /_sablier_embed;
        set $embed_up "embed-test:80";
        proxy_pass http://$embed_up/;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
    location = /_sablier_embed {
        internal;
        proxy_pass http://sablier_api/api/strategies/blocking?names=embed-test&session_duration=2h&timeout=120s;
        proxy_pass_request_body off;
        proxy_set_header Content-Length "";
    }

    # ─── /api/llm/ → llm-test ────────────────────────────────────────────
    location /api/llm/ {
        auth_request /_sablier_llm;
        set $llm_up "llm-test:80";
        proxy_pass http://$llm_up/;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
    location = /_sablier_llm {
        internal;
        proxy_pass http://sablier_api/api/strategies/blocking?names=llm-test&session_duration=2h&timeout=120s;
        proxy_pass_request_body off;
        proxy_set_header Content-Length "";
    }
}
Pattern. Each route is two location blocks: the public one with auth_request, and an internal helper that calls Sablier. To add a new model, copy the pair, change the path, the names= parameter, and the upstream variable. Reload nginx with docker compose exec sablier-nginx nginx -s reload.

9. Your model containers

Model containers are not in the main docker-compose.yml — that's the stack itself. The models live in their own compose file and are brought up without starting: they exist in Docker's database (visible to Sablier) but stay Stopped until Sablier wakes them.

The mock model server (for demos and integration testing)

To exercise the full stack without needing a real GPU, the example ships a tiny single-file Python service that simulates a model server. It has a configurable startup time (per-container, via env var) so you can demonstrate cold-start latency, eviction timing, and recovery — behaviour that nginx-as-stand-in can't show.

mock-model/main.py

"""Mock model service for the Sablier opinionated stack.

Simulates a model server's lifecycle:
  1. On startup: sleep STARTUP_SECONDS to simulate weight loading.
  2. Once "loaded": start the HTTP server and respond 200 to /health.
  3. /          - identifying string with model name and configured delays.
  4. /infer     - sleeps INFERENCE_SECONDS, then returns the same string.
  5. /health    - 200 OK once loaded; 503 while still warming up.

Configurable via environment variables (with defaults):
  MODEL_NAME=mock-model
  STARTUP_SECONDS=3
  INFERENCE_SECONDS=0
  PORT=80
"""

mock-model/Dockerfile

FROM python:3.12-alpine
WORKDIR /app
COPY main.py /app/main.py
EXPOSE 80
CMD ["python", "main.py"]

Build the image once:

docker build -t mock-model:latest mock-model/

compose.models.yml — declarative model definitions

Each model is one service in compose.models.yml. The startup time and inference time are env-var parameters on the container, set per service so each model behaves differently — exactly what you want when comparing eviction strategies. Replace image: mock-model:latest with your real model server's image when wiring this up for production. The Sablier labels and the healthcheck shape are what matters; the image is yours.

name: sablier-models

x-model: &model-defaults
  image: mock-model:latest
  networks: [sablier-net]
  restart: "no"
  healthcheck:
    test: ["CMD-SHELL", "wget -q -O - http://127.0.0.1/health >/dev/null 2>&1 || exit 1"]
    interval: 1s
    timeout: 2s
    retries: 3
    start_period: 1s

services:
  whisper-test:
    <<: *model-defaults
    container_name: whisper-test
    environment:
      MODEL_NAME: whisper-test
      STARTUP_SECONDS: "3"        # <-- per-container parameter
      INFERENCE_SECONDS: "0.5"
    labels:
      sablier.enable: "true"
      sablier.group: "models"
      sablier.peak_vram_mb: "2000"
      sablier.priority: "10"

  embed-test:
    <<: *model-defaults
    container_name: embed-test
    environment:
      MODEL_NAME: embed-test
      STARTUP_SECONDS: "5"
      INFERENCE_SECONDS: "0.2"
    labels:
      sablier.enable: "true"
      sablier.group: "models"
      sablier.peak_vram_mb: "4000"
      sablier.priority: "50"

  llm-test:
    <<: *model-defaults
    container_name: llm-test
    environment:
      MODEL_NAME: llm-test
      STARTUP_SECONDS: "8"        # bigger model, slower cold start
      INFERENCE_SECONDS: "1.5"
    labels:
      sablier.enable: "true"
      sablier.group: "models"
      sablier.peak_vram_mb: "5000"
      sablier.priority: "80"

networks:
  sablier-net:
    name: sablier-net
    external: true

Materialise the containers (the --no-start flag is the critical bit — they're created but not started):

docker compose -f compose.models.yml up --no-start

# Verify they exist but are stopped:
docker ps -a --filter 'name=^/(whisper|embed|llm)-test$' \
  --format 'table {{.Names}}\t{{.Status}}'
Why external: true? The sablier-net network is created by the main stack (docker-compose.yml). Declaring it as external in compose.models.yml means compose will reuse the existing network instead of trying to create a second one. Bring up the main stack first.
Healthcheck gotcha. Use http://127.0.0.1/ rather than http://localhost/. Alpine resolves localhost to ::1 first, and most model servers (including stock nginx and the mock-model service) listen on IPv4 only. Sablier marks a Status=Running but Health=Unhealthy container as error, not ready, so the request will time out at 500 even though the container is fine.

For your real models

Replace the image: field with your real model server's image. The labels and healthcheck shape stay the same:

  • sablier.enable=true — required to register with Sablier.
  • sablier.group=models — optional; lets you start multiple containers as a unit via ?group= on the API.
  • sablier.peak_vram_mb=N — opt-in to VRAM management. Without this label, the container falls back to plain time-based eviction.
  • sablier.priority=N — lower = evict first. Default 50.
  • healthcheck: — Sablier reports Ready only when the container is healthy. Without a healthcheck, Sablier assumes ready as soon as the container is Running, which is usually premature for model servers that take seconds to load weights.

create-models.sh — alternative one-liner approach

If you'd rather not maintain a second compose file, an equivalent bash script is in the example directory at create-models.sh. It uses docker create directly. Functionally identical, just less declarative. Pick whichever feels more natural for your operations workflow.

10. Bring it up

cd /opt/sablier-stack

# 1. Build the mock-model image (skip if you're using real model images)
docker build -t mock-model:latest mock-model/

# 2. Start the stack (Sablier + nginx). This also creates the sablier-net network.
docker compose up -d

# 3. Materialize the model containers without starting them.
docker compose -f compose.models.yml up --no-start

# Verify nginx is up
curl http://localhost:8080/healthz
# → ok

# Trigger a cold start of whisper-test (STARTUP_SECONDS=3, plus healthcheck delay)
curl http://localhost:8080/api/whisper/
# → Hello from whisper-test (startup=3.0s, infer=0.5s)

# Force an eviction — the three declared peaks (2000+4000+5000=11000) exceed
# the 8000 MB budget, so requesting llm-test evicts the lowest-priority loaded models.
curl http://localhost:8080/api/embeddings/
curl http://localhost:8080/api/llm/
docker logs sablier 2>&1 | grep evicting
# evicting instance for VRAM pressure victim=whisper-test for=llm-test

Each model's startup time is independent: whisper-test is "ready" in ~3 s, embed-test in ~5 s, llm-test in ~8 s. Tweak the STARTUP_SECONDS values in compose.models.yml to match the cold-start cost of your real models.

A verify.sh script next to the compose file runs the same sequence as smoke tests with assertions. Use it after first bring-up or after changes:

./verify.sh
# Summary: PASS=8  FAIL=0
SIGTERM matters. Eviction speed is bounded by how fast your model server stops. Containers that ignore SIGTERM force Docker to wait the full --stop-grace-period (default 10 s) per container before SIGKILL. With three concurrent evictions, that's 30 s of artificial latency. The mock service in this example installs a SIGTERM handler so it stops promptly; your real model servers should too. Alternatively, set stop_grace_period: 2s in the service block to bound the wait.

11. Sizing the budget

Two values to set: --vram.total-mb and --vram.headroom-mb.

Total. Set this to what's available to Sablier-managed containers. If you have a 24 GB GPU and a long-running process always uses 4 GB outside Sablier's control, set total=20000. Sablier doesn't measure; it accounts.

Headroom. A buffer that absorbs imprecision. Reasons it matters:

  • Real VRAM consumption can briefly exceed declared peak during model warm-up (KV cache filling, framework allocations).
  • If a request arrives while a previously-evicted container is still in the process of stopping, the freed VRAM may not yet be available to the GPU driver.
  • Padding lets you avoid OOM-kills caused by these timing windows.

5–10% of total is reasonable. For a 24 GB card with serious models, 1500 MB is comfortable.

12. Setting priorities sensibly

Priority is an integer; lower values get evicted first. The eviction algorithm sorts by (priority asc, last_used asc), so:

  • Two containers, same priority, the one used least recently goes first.
  • Two containers, different priority, lower priority goes first regardless of recency.

A pragmatic schema:

PriorityUse for
10Cheap-to-restart, infrequently used. (e.g. small embedding models, Whisper-tiny.)
30Mid-cost restart. (e.g. medium models, faster-whisper-base.)
50 (default)Average, no strong preference.
70Expensive cold start, used regularly. (e.g. 7B–13B LLMs.)
90Very expensive cold start, you really want this kept loaded. (e.g. 70B LLMs, large multi-modal models.)

Reserve 100 for "must not be evicted unless absolutely no other option" — note that even a priority-100 container can be evicted if it's the only candidate left and the request truly needs the space. The algorithm returns an error only when evicting everything wouldn't be enough.

13. Day-to-day operations

Adding a new model

  1. Add an auth_request + location pair to nginx/conf.d/server.conf.
  2. Add a service block to compose.models.yml (or a create_model line to create-models.sh if you took the bash path).
  3. Materialise the new container: docker compose -f compose.models.yml up --no-start.
  4. Reload nginx: docker compose exec sablier-nginx nginx -s reload.
  5. Verify: curl http://localhost:8080/api/<new-path>/.

Updating an existing model image

docker pull yourorg/whisper:newtag

# Edit compose.models.yml to bump the image tag, then force a recreate
# (compose detects the image change and updates the stopped container):
docker compose -f compose.models.yml up --no-start --force-recreate whisper-test

Sablier picks up the new container labels on its next event-stream notification (sub-second). No Sablier restart needed.

Restarting Sablier without losing state

Sablier's in-memory store doesn't persist. Restart drops state, but the auto-stop-on-startup=true behaviour will stop any currently running model containers as a clean reset. The next request to nginx will cold-start them again. This is intentional and safe — there's nothing to lose because Sablier was the source of truth, and the docker daemon still remembers the containers exist.

Logs to watch

docker logs -f sablier        # eviction decisions, request handling
docker logs -f sablier-nginx  # access log + auth_request errors
docker stats                  # actual resource usage

14. When you have a non-AI service in the mix

If you also run a small admin tool, a Whisper UI, or anything else that doesn't need VRAM, don't give it sablier.peak_vram_mb. Just set sablier.enable=true. That container then:

  • Doesn't count against the VRAM budget.
  • Doesn't trigger eviction of others.
  • Can't be evicted by pressure.
  • Falls back to time-based eviction, expiring per the route's session_duration.

Pair it with a shorter session_duration in the auth_request URL (e.g. session_duration=10m) so it actually cleans up.

15. Troubleshooting

nginx returns 500 "auth request unexpected status" — POSTs only

If GETs work but POSTs (file uploads, JSON bodies) return 500 in well under a second, sablier is rejecting the auth_request with HTTP 400 "Validation Failed." nginx's auth_request module forwards the original request method and Content-Type to the auth upstream by default. With proxy_pass_request_body off; the body is dropped, but if the original request was a POST with Content-Type: multipart/form-data, sablier's gin binder tries to parse a body that isn't there and returns 400.

Fix: force every auth_request to look like a clean GET regardless of the original method. Add to each internal _sablier_* location:

proxy_method GET;
proxy_set_header Content-Type "";

This is in the example server.conf. If you wrote your own nginx config from scratch, copy these two lines.

Upstream model receives the wrong path (404 or unexpected 405)

Symptom: GETs work, POSTs come back as 405 "Method Not Allowed" with a JSON body from the model server, or you see the upstream container's log show requests against the location prefix instead of the stripped path (e.g. POST /api/whisper/asr instead of POST /asr).

Cause: proxy_pass with a variable doesn't strip the location prefix the way proxy_pass with a literal does. The trailing-slash trick only works with literal upstreams.

# DOES NOT strip the prefix (variable + trailing slash):
location /api/whisper/ {
    set $whisper_up "whisper-test:80";
    proxy_pass http://$whisper_up/;     # whisper sees /api/whisper/foo
}

# DOES strip the prefix (variable + explicit rewrite):
location /api/whisper/ {
    set $whisper_up "whisper-test:80";
    rewrite ^/api/whisper/(.*)$ /$1 break;
    proxy_pass http://$whisper_up;      # whisper sees /foo
}

Use the second form whenever you need a variable (which you do, for lazy DNS). Mock-model servers with a catch-all root handler will hide this bug — symptoms only appear when you swap to a real model that has specific routes.

nginx returns 500 "auth request unexpected status" — GETs too

The auth_request returned a non-2xx response. Cause is almost always one of:

  • The model container's healthcheck never goes Healthy. Check docker inspect <name> --format '{{json .State.Health}}'. The IPv6 trap (localhost→::1) is the most common.
  • Sablier's blocking timeout (?timeout= in the URL, default 120 s) is shorter than the cold-start time. Bump it.
  • The container failed to start at all (image missing, command broken). Check docker logs <name>.

Insufficient VRAM error on a request

You'll see an HTTP 500 with a body like:

{"detail":"... insufficient VRAM and no further eviction candidates: need 20500 MB (incl 500 headroom), can free at most 8000 MB", ...}

The requested container's declared peak (plus headroom) exceeds your total budget even with everything else evicted. Either bump --vram.total-mb (if you have the actual hardware) or fix the container's peak_vram_mb if it's overstated.

Container stays unhealthy

Check the healthcheck command works inside the container:

docker start whisper-test
docker exec whisper-test wget -q -O - http://127.0.0.1/
docker stop whisper-test

nginx can't resolve the upstream

If the upstream container has been removed, nginx will return 502 because the variable in proxy_pass doesn't resolve. Re-create with docker compose -f compose.models.yml up --no-start (or ./create-models.sh if you took the bash path).

16. What this setup is not

  • Multi-host. One Sablier per Docker host. For a cluster, switch to the Kubernetes provider — but that's outside this opinionated path.
  • HA. Single nginx, single Sablier. If either dies, traffic fails. Use a process supervisor or compose's restart: unless-stopped as a band-aid.
  • For browser users with loading pages. The dynamic strategy (HTML interstitial) needs a proxy plugin that can render templates. auth_request can't. If you need that for browser-facing UIs, switch to Traefik with the official Sablier plugin.
  • Auto-detecting GPU memory. You set --vram.total-mb by hand. Auto-detection via nvidia-smi would be ~20 lines but it's not in this build, deliberately — you usually want manual control on shared GPUs anyway.

End of guide. For the underlying design rationale and test report covering the eviction algorithm itself, see VRAM_TEST_REPORT.html.
